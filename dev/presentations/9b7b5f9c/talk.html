Safety · 10 / 20

Validate first; publish once

capture → plan → overlay validate → lock → rebuild plan → transact → verify
  1. Capture every target and repository input relevant to the package.
  2. Build the complete merged final state in an overlay view.
  3. Reject path, package, conflict, and repository-validation failures.
  4. Acquire the repository-wide mutation lock and rebuild the plan.
  5. Publish the file set through one durable transaction protocol.
A preflight failure mutates no target. The plan checked before locking cannot go stale unnoticed.
Safety · 11 / 20

Handled failure rolls back; uncertainty becomes durable

Before commit point

  • restore every old byte and mode
  • verify exact rollback
  • return failure only after proof

Crash or uncertain cleanup

  • retain a typed transaction journal
  • prepared → converge to all-old
  • committed → verify all-new, then clean
Every later mutating JIT command performs mandatory recovery before normal repository services start.

Hard-earned lesson · 17 / 20

A universal safety boundary created a process boundary bug

gate evaluate [holds recovery locks] → checker → mutating jit child [waits 5s] → timeout
  • The universal mutation boundary retained bootstrap and repository locks for the whole command.
  • Lock reentrancy was in-process only; external checkers are child processes.
  • docs-mechanical spawned jit invariant render, so parent and child deadlocked.

Root cause: a correct recovery boundary carried an in-process lock-lifetime assumption across a process boundary.

Hard-earned lesson · 18 / 20

Release, execute, reacquire, recover

release session → run checker child under ordinary locks → reacquire + recover → persist verdict
  1. Temporarily drop the evaluator's retained recovery session.
  2. Let the checker and nested JIT commands use the ordinary lock chain.
  3. Reacquire serialization and recover any checker-side journal.
  4. Only then persist the gate result.
Regression tests prove both sides: nested mutating checkers pass, and unrelated processes still serialize.

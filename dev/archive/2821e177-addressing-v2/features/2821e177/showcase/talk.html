Problem · 3 / 16

Two grammars fighting over a colon

  • Labels are namespace:value — the colon is the load-bearing separator.
  • Rule ids also carried colons: default:namespace-unique:type.
  • @ was not even a legal label-value character — a project-scoped link like enforces:@/… could not be authored at all.
  • Old addresses were kindless (@/INV-01): ambiguous the moment two kinds share a self-id.
Epic 90a2dbfd (declarative kinds) had to defer "rule/gate as items" for exactly this collision. Addressing v2 is that thread, reopened and finished.
Scheme · 4 / 16

One uniform, kind-segmented scheme

@[<project>]/<kind>/<self-id>   |   @/issue/<short-id>/<kind>/<self-id>
  • Project items: @/invariant/INV-DAG-ACYCLIC, @/rule/coverage-preview, @/gate/cargo-ci
  • Issue items: @/issue/0597febe/requirement/REQ-01
  • Input sugar: 0597febe/REQ-01 — kind inferred from the self-id shape
  • Colon: reserved solely for the label separator; never overloaded inside a value
Scheme · 5 / 16

What the core required

  • A structural parser with per-(scope, kind) uniqueness and strict sugar expansion
  • The label-value grammar widened to admit @-prefixed /-paths — with every value re-split site audited
  • Resolver rewired to the kind-segmented form; the legacy kindless arm removed in a clean cut (decision D11: no compatibility shim)
  • Minted output flipped together with resolution: every id jit item list prints round-trips through jit item show
Items · 6 / 16

Rules become addressable items

  • Origin split out of the self-id: default:label → name label, origin = "default"
  • Colon-bearing rule names are now rejected at load time
  • Registry-first kind over .jit/rules.toml — declared in config, zero new engine code
[item_kinds.rule]
scope = "project"
source = { toml = ".jit/rules.toml", table = "rules", id-field = "name" }
# ⇒ addressable at @/rule/<name>
Items · 7 / 16

Gates follow — on a migrated store

  • gates.json → gates.toml with schema parity; a dedicated store mirrors the ruleset store; no consumer reads the old file
  • Gate registry mutations are event-logged (INV-EVENT-LOG) — define, remove, and preset application all leave an audit trail
  • jit init scaffolds the empty registry; every gate is addressable at @/gate/<key>
jit item show @/gate/cargo-ci resolves to the gate definition — same mechanism as invariants and requirements.
Links · 8 / 16

Bindings and links resolve to real items

Multi-jit · 11 / 16

The multi-jit address form (identity now, federation later)

  • Projects gain a canonical name: [project] name, seeded by jit init, validated on every config write
  • Bare @ = local shorthand; @<own-name> also resolves locally
  • @<other-project> is parse-valid and returns a typed not-resolvable error — no network, no registry, no guessing
jit item show @gf2/invariant/INV-01 → "project 'gf2' is not the local project; only local resolution is available."

Impact · 13 / 16

How this enhances jit

  • One grammar for all knowledge: invariants, requirements, decisions, risks, definitions, rules, gates — one address shape, one resolver
  • Traceability: work items cite the exact rule or gate they enforce; bindings are checked, not prose
  • No more grammar collisions: colon-free values end the label/id conflict that blocked a prior epic
  • Config over code: new addressable kinds are declared in TOML — the engine bakes in none
  • Dogfooded: this repo runs on the scheme it shipped

## 2. Technical soundness and architectural fit

- **Approach:** Keep release work at dependency, workflow, packaging, and documentation boundaries. The four product surfaces are already concrete workspace/package outputs (`Cargo.toml:1-8`, `crates/jit/Cargo.toml:14-16`, `crates/server/Cargo.toml:13-19`, `web/package.json:1-12`, `mcp-server/package.json:1-12`), so the plan adds no engine-level release or Docker concepts. This follows charter D-9's capability-preservation boundary (`dev/vision/9db27a3a-charter.md:151-162`) and the investigation's already-done/valid-and-open classification (`dev/active/8b05a612-investigation.md:9-21`).
- **Reuses / integrates with:** The exact-MSRV CI job already reads workspace `rust-version` and builds that compiler (`.github/workflows/ci.yml:82-134`); the recency command derives from the same manifest instead of adding another version literal. Rust 1.97 is the researched baseline, and the comparison/pre-tag handoff is specified at `dev/active/8b05a612-research.md:52-59`. Source freeze, candidates, rehearsal, and final tag carry one 40-hex SHA. After live-state preflight, recency is the final validation; its exact result is sealed into the prepared artifact, then only that atomic upload and one-use App-token mint precede annotated non-force tag creation at the same SHA.
- **Reuses / integrates with:** `jit-server` validates an existing data directory, watches it, and derives the project name from its parent (`crates/server/src/main.rs:61-90`). It already nests API routes under `/api` and serves either `--web-dir` assets or embedded assets (`crates/server/src/main.rs:104-129`); the health route is consequently `/api/health` (`crates/server/src/routes.rs:33-36,66-73`). `/api/search`, however, searches from `Path::new(".")`, and the web client consumes its issue/document results (`crates/server/src/routes.rs:297-299`; `web/src/api/client.ts:41-49`). The image therefore binds the repository at `/repo`, sets `WORKDIR /repo`, passes `/repo/.jit`, and uses that one server rather than introducing a proxy or storage adapter.
- **Grounding (from investigation):** Embedded web is **valid but build-order-sensitive**: `crates/server/build.rs:4-18` creates an empty `web/dist` stub if the web build has not run. Native packaging, Docker, and the clean-room rehearsal build web first and test both `/` SPA fallback and `/api/health` (`dev/active/8b05a612-investigation.md:20,47-50`).
- **Grounding (from investigation):** Security enforcement is **valid-and-open**: tool installation is currently suppressed and all three audits are advisory (`.github/workflows/security-audit.yml:37-57`), CI describes security as separate/manual (`.github/workflows/ci.yml:314-316`), and release does not depend on it (`.github/workflows/release.yml:128-132`). The reusable workflow uses the fail-closed commands justified at `dev/active/8b05a612-research.md:61-69` only after separate lock-domain remediation has made each boundary green.
- **Grounding (from investigation):** Release identity and publication are **valid-and-open**: current component versions disagree and every `v*` tag is accepted (`crates/jit/Cargo.toml:1-5`, `crates/server/Cargo.toml:1-5`, `mcp-server/package.json:1-4`, `web/package.json:1-5`, `.github/workflows/release.yml:3-7`). The existing workflow packages but does not install-smoke, publish npm, include license texts/SBOM, or prove normal/security suites (`.github/workflows/release.yml:12-179`). Reusable exact-SHA dependencies, pre-tag authorization, SPDX artifacts, and attestation follow the researched job graph and artifact contract (`dev/active/8b05a612-research.md:6-14`).
- **Grounding (from investigation):** GitHub invocation identity is **valid-and-open**: a manually supplied checkout SHA can differ from `github.sha`, while reusable workflows, OIDC claims, and attestations continue to identify the caller event and workflow commit. The candidate path therefore begins with a protected, non-movable candidate-tag push; accepts no checkout-ref input; invokes same-repository workflows by local path; and verifies the event/ref/SHA, caller and called-workflow SHAs, repository IDs, OIDC claims, and exact attestation subjects before each producer or publication command (`dev/active/8b05a612-research.md:11-15`).
- **Grounding (from investigation):** Tag authentication is **valid-and-open**: `GITHUB_TOKEN` events do not chain workflows, and ruleset bypass is granted to an actor, not a workflow filename. Ownership is deliberately split: the authority leaf owns account-side App/rulesets/environments/immutable settings plus one fixed-ref token/create/readback primitive; it owns no execution YAML. The dependent orchestration leaf exclusively owns candidate/final workflow triggers, job DAGs, transitions, resume behavior and cross-workflow fixtures, invoking that primitive through typed exact-ID inputs/outputs. This prevents two workers from implementing the same tag path (`dev/active/8b05a612-research.md:14-20`).
- **Grounding (from investigation):** External Action identity is **valid-and-open**: current critical workflows use movable major or branch references. Every external Action or reusable workflow directly invoked anywhere on the CI, security, candidate, tag-authorizer, or publication paths is therefore pinned to a full 40-character commit SHA; a recursive parsed-workflow/composite scan enforces that property and a reviewed update procedure records the upstream release and permissions delta (`dev/active/8b05a612-research.md:16-19`).
- **Grounding (from investigation):** npm publication is **valid-and-open**, and the channel is absent. Bootstrap creates/verifies a pre-v1 public package and revokes its temporary credential; release administrators bind a protected reviewer-gated secret-free `npm-publish` environment to the exact direct-publish workflow. Because official docs provide no v1 stage-retention contract, rehearsal uses the retained tarball while public 1.0.0 is absent. After final-tag completion, OIDC publishes that exact tarball under npm-publish prepared/completed/recovery evidence; no v1 stage, 2FA handoff, token, or repack exists.
- **Grounding (from investigation):** Docker consolidation is **valid-and-open**. The current runtime installs nginx and Node, copies unused MCP, runs as root, uses `/data`, and launches background processes followed by `tail` (`Dockerfile:39-88`, `docker/entrypoint.sh:4-19`); Compose exposes three services on a detached named volume (`docker-compose.yml:3-62`). Because repository search uses the server process working directory, the replacement must start from mounted `/repo` and prove web-consumed issue/document search, not only health/storage access. The exhaustive active consumer roster is fixed at `dev/active/8b05a612-investigation.md:23-31`, and no removal lands before those consumers are migrated.
- **Grounding (from investigation):** Server termination is **valid-and-open** and precedes Docker packaging. The current `axum::serve(listener, app).await` has no shutdown future; the web client keeps `/api/events/stream` open; and even SSE cancellation would not bound a stalled ordinary connection (`crates/server/src/main.rs:135`; `crates/server/src/routes.rs:1018-1019`; `crates/server/src/sse.rs:16-31`). The focused leaf adds `axum-server` 0.8 `Handle`, a five-second `GRACEFUL_DRAIN_TIMEOUT`, and one `CancellationToken` in `AppState`. Signal cancellation ends SSE/keepalive, then bounded handle shutdown waits only five seconds, logs remaining connection count, force-closes stalled connections, and returns at least five seconds before the ten-second container stop timeout (`dev/active/8b05a612-research.md:42-52`).
- **Grounding (from investigation):** Docker publication is **valid-and-open**. The current workflow skips pull requests, builds four image shapes, and publishes movable aliases with no runtime smoke (`.github/workflows/docker.yml:3-15,30-41,68-91,93-150`). The selected release transport is an OCI-layout tar produced by the Buildx `oci` exporter with attached max-provenance and SBOM manifests. `skopeo inspect --raw` plus `skopeo manifest-digest` records the top-level attested index `D_index` and its Linux/amd64 runnable manifest `D_run`; `skopeo copy --preserve-digests` copies only `D_run` to Podman's containers-storage for smoke without changing the source archive; final publication uses `skopeo copy --all --preserve-digests oci-archive:... docker://ghcr.io/...:1.0.0` and requires the resulting digest to remain `D_index`. The archive SHA-256 detects transport corruption, `D_run` is the attestation/runtime subject, and `D_index` is the GHCR release identity (`dev/active/8b05a612-research.md:32-40`).
- **Grounding (from investigation):** GitHub Release immutability is **valid-and-open**. Repository immutable releases are enabled before source freeze. Candidate assembly creates a draft bound to the protected annotated candidate tag, uploads every candidate/evidence/recovery asset, verifies it, and publishes an intentional public immutable candidate prerelease before rehearsal. Rehearsal reads those exact assets. Final publication copies the same bytes into a final draft and publishes once. Immutable status and release attestations bind tag/SHA/assets; permissions and endpoint fixtures ensure post-tag recovery identities cannot edit/delete/replace escrow or final assets (`dev/active/8b05a612-research.md:17-20,85-99`).
- **Grounding (from investigation):** Durable evidence is **valid-and-open**. Actions artifacts remain the exact-ID pre-tag transition ledger at 90-day retention, but they are not durable escrow and may return 410. The immutable candidate prerelease holds every publishable byte/root/evidence parent; rehearsal records its numeric release/asset IDs/digests; the final annotated tag embeds a compact complete authorization manifest. After tag creation, recovery can reconstruct trust from escrow+tag+exact live state and write fresh completed evidence. All final authorization and channel mutation/recovery entry points share constant Actions group `jit-v1.0.0-publication` with `cancel-in-progress:false`; a replaced pending run has made no mutation and is explicitly redispatched with the same parent ID.
- **Grounding (from investigation):** Documentation deduplication is **valid-and-open**. Install, Docker, source, and MCP procedures overlap across `README.md:38-58`, `INSTALL.md:15-254`, `docs/how-to/deployment.md:1-186`, and `mcp-server/README.md:21-75`. The active-consumer sweep at `dev/active/8b05a612-investigation.md:29-39` defines the blast radius; archive/session evidence remains unchanged, and all live entry points retain navigation to canonical pages under `@/inv/single-source-prose`.
- **Grounding (from investigation):** Source installation is **valid-and-open**. The supported source procedure currently assumes a Git checkout but the release publishes no source distribution. Candidate tooling will use a pinned Git implementation and committed export-ignore policy to produce normalized `git archive` tar bytes at the source-freeze SHA, deterministic no-timestamp compression, SHA-256, SPDX file inventory, and exact-subject provenance. The extracted archive—not a checkout—must pass `cargo install --path crates/jit --locked` and the canonical source procedure before the same bytes enter the immutable release.
- **Architecture boundary:** Dependency updates may require local API migrations, but those migrations stay with the affected Rust, web, or MCP consumer in the same remediation item. Packaging code does not enter `crates/jit/src/domain/`, graph, or storage. The focused product-code prerequisite is server-process lifecycle across `main.rs`, `AppState`/router, and SSE; Docker consumes it without adding a supervisor or changing API/storage semantics. All source changes land before freeze. Later leaves are execution-only: Actions artifact IDs carry append-only transition state while the immutable candidate prerelease carries durable bytes/recovery parents; neither repository files nor a new database are introduced. App, candidate-escrow, npm, GHCR, and final-release authorities stay isolated in protected jobs.

## Decisions

- **D1 — Capability boundary:** chosen **preserve the native CLI, Rust server/API, built web UI, and MCP server while cutting only redundant packaging, deployment, aliases already scheduled elsewhere, and repeated prose**. Rejected: broad feature cuts (would violate the v1 capability contract), retaining every delivery shape (multiplies support/security cost without a distinct outcome).
- **D2 — Advisory remediation and Rust lock ownership:** chosen **three ecosystem remediation leaves; Rust waits for core child `73482aa1`, then bounded-shutdown adds audited `axum-server`/`tokio-util` in the same serialized Cargo manifest/lock domain; only afterward the reusable blocking audit workflow is enabled over the combined final graph**. Rejected: cross-ecosystem mega-change, parallel core/remediation/shutdown Cargo.lock edits, enabling enforcement before the last dependency addition, or blanket ignores.
- **D3 — Disjoint release ownership:** chosen **authority owns account-side App/rulesets/environments/immutable settings, runbooks and fixed-ref primitive/unit fixtures; npm bootstrap depends on that environment and owns package/scope/bootstrap plus npm-side trusted-publisher binding; MCP tooling owns pure pack/publish/readback interfaces; orchestration exclusively owns release-execution YAML, DAG, transitions/concurrency/recovery and hosted fixtures, composing both typed interfaces**. Rejected: overlapping environment/YAML/transition ownership, duplicate tag or recovery fixtures, GITHUB_TOKEN chaining, PATs, ref/latest authority, movable Actions or credential crossover.
- **D4 — Version, MSRV, and tag authority:** chosen **derive versions/MSRV, rehearse exact SHA, run live-state+recency immediately before prepared upload/App tag, and exact-readback complete. Existing exact tag may recover from its prepared ID; absent tag supersedes stale preparation and repeats full preflight/MSRV under a new prepared ID**. Rejected: post-tag recency, stale absent-tag reuse, deferred public preflight, manual tag, workflow literals, movable tag, or format/product conflation.
- **D5 — Native and source artifact contract:** chosen **one Linux x86_64 musl archive plus one deterministic normalized git-archive source distribution from the same freeze SHA, both license/checksum/SPDX/provenance covered; native extracted-binary/server smoke and source extracted no-Git `cargo install --path crates/jit --locked` plus canonical-procedure smoke; publish the retained rehearsed bytes**. Rejected: checkout-only source instructions, GitHub auto-generated source snapshots as the tested asset, rebuild-at-publication, the current un-smoked archives, or a standalone web archive.
- **D6 — MCP bootstrap, native prerequisite, escrow rehearsal, and OIDC publication:** chosen **after authority creates the protected environment, bootstrap/verify pre-v1, revoke the credential and bind npm-side trusted publishing; MCP tooling supplies pure pack/publish/readback interfaces; orchestration builds/attests/smokes one tarball with retained native jit, escrows and rehearses that asset, then after final tag directly publishes it under prepared/completed/recovery evidence**. Rejected: overlapping environment/workflow ownership, v1 staging, token/manual command, pre-tag publish, source publish, rebuild/repack or listing authority.
- **D7 — Server lifecycle, Docker identity, ownership, transport, and tags:** chosen **`axum-server` 0.8 Handle plus shared SSE CancellationToken; a five-second application drain/force-close deadline inside a ten-second container stop timeout; active-SSE EOF and deliberately stalled ordinary-connection real-process/container tests with exit 0; then one exec-form non-root jit-server PID-1 image with `WORKDIR /repo`, issue/document search, OCI-layout max-provenance/SBOM, D_run/D_index and digest-preserving Skopeo; main/SHA development tags and one release tag**. Rejected: indefinite Axum drain, SSE-only cancellation, listener-only shutdown, runtime SIGKILL, init/shim/shell supervision, image-filesystem search, Docker load/archive, rebuild/non-preserving copy, split/root `/data`, or mutable release aliases.
- **D8 — Documentation ownership:** chosen **one canonical home per binary/source install, deployment, MCP, release, compatibility, and MSRV fact with concise linked entry points; all docs land before source freeze and rehearsal executes frozen prose**. Rejected: post-candidate doc edits, synchronizing repeated walkthroughs, deleting entry-point context, or rewriting archive evidence.
- **D9 — Core and profiles completion before production-readiness freeze (explicit human steering):** chosen **keep the current DAG organization, create no v1 checkpoint, require both core epic `6eb585bc` and profiles MVP `9b7b5f9c` to reach `Done`, and attach both directly to “Freeze the exact integrated v1.0 source” at breakdown; rehearsal verifies both accepted contracts**. Rejected: a checkpoint, Rejected/other terminal satisfaction, incomplete freeze, rehearsal-only edges, omitting profiles, or duplicate core work. Rust remediation still serializes on `73482aa1`.
- **D10 — Frozen candidates, escrow, rehearsal, final tag, direct npm, then GHCR/GitHub:** chosen **exact-ID candidate event completion; produce/attest root; publish every byte/evidence parent in an immutable public candidate prerelease; rehearse directly from escrow; fresh grouped final preflight/MSRV/tag transition; direct OIDC publish escrowed MCP; then grouped GHCR/final-GitHub publication from escrow**. Rejected: Actions-only byte retention, staged v1, later source/rebuild, refs/secrets, uncoordinated or early publish, untrusted push publisher, or mutable assets.
- **D11 — Cross-run evidence, mutex, retention, and recovery:** chosen **90-day exact-ID Actions transitions plus durable immutable candidate escrow; one literal `jit-v1.0.0-publication` group with `cancel-in-progress:false` across every final mutator/recovery; explicit same-parent redispatch after pending replacement; rehearsal records escrow identities and final tag embeds a complete compact recovery manifest; Actions 410 recovers from escrow+tag+live state; stale absent-tag preparation gets fresh authorization, while tag creation is irreversible**. Rejected: Actions as sole post-tag store, mutable/latest discovery, external DB, undefined lock, cancelling a running mutator, blind retry, rerun ambiguity, or post-tag rebuild/replacement.
- **Assumptions** (where intent stayed underspecified): the supported native binary target for v1.0 is Linux x86_64 musl, matching the current release scope — expanding operating-system/architecture coverage would require an owner criterion change; GitHub Release, npm package `@erankavija/jit-mcp-server`, and GHCR are the authorized public channels named by the current manifests/workflows and research — unavailable account-side configuration fails publication rather than selecting a substitute channel; external epics may evolve internally, but freeze waits for both named epics in `Done` and rehearsal consumes only their accepted public contracts.

A place for everything

Issue-based artifact layout and serviceable archival in JIT

Epic 8e071e18  ·  just-in-time  ·  2026-07-27

Every command output on these slides was captured from a real run of jit 0.2.1 (commit 758a44d3). Product behaviour is shown on a freshly initialized repository, so no claim depends on this project's own configuration.

Feature introduction

What shipped

An issue owns one directory per configured area, a command resolves it, and the archival mechanism can service every artifact that lands there.
  • Configuration declares which development areas organize artifacts per issue.
  • The directory name is derived from the issue's identity — never from its title.
  • Archival classifies every configured area, so no artifact class is unreachable.
  • Planning warns about the prose citations a relocation would break, and rewrites none of them.
The through-line: a path is resolved by the tool rather than spelled out by whoever is writing the file.
Motivation

Two defects, found by an epic's own review

The mechanism could not service a whole artifact class. jit archive refused any selected root that was neither managed, permanent, nor already archived. The shipped default named three managed areas; dev/presentations was not among them, so archiving a slide deck had to be hand-rolled with git mv.

That bypass skipped the planner's reference remapping. A document reference dangled and jit validate hard-failed until it was repaired by hand.

A workaround that skips the mechanism also skips everything the mechanism guarantees. The failure surfaced two steps later, in an unrelated command.
Motivation

The flat layout did not scale

172 artifacts sat at area root as <short-id>-<artifact>.md. Most were owned by issues that had been terminal for months.

The one place that already derived a directory name from an issue fell back to the issue title, which produced names truncated mid-word. The archive contained its own counter-example:

dev/archive/a9b5dd08-use-strategic-label-slugs-in-archive-directory-n/

The directory whose issue was titled “Use strategic label slugs in archive directory names” — cut off two characters into the last word.

Design

The convention

An issue's artifact directory is <area>/<short-id>-<slug> when the issue resolves a single membership value, and <area>/<short-id> otherwise. Filenames inside it carry no short-id prefix.
  • The slug comes from a membership label — the issue's type: label, that type's membership namespace, and a single value of it.
  • Titles are excluded by construction, so renaming an issue never moves its directory.
  • The directory names the issue, so each file names its own artifact: plan.md.
Pre-existing flat files are tolerated rather than restructured in place.
The resolver

jit doc dir — with a membership label

$ jit doc dir c8d742fa dev/active
dev/active/c8d742fa-payment-reconciliation

$ jit doc dir c8d742fa dev/presentations
dev/presentations/c8d742fa-payment-reconciliation

The issue is titled “Payment reconciliation” and carries type:epic with epic:payment-reconciliation. The slug is the label value; the title coincidentally matches and contributes nothing.

The caller names the area. Everything after it is derived.

The resolver

Obtain the path; do not compose it

$ jit doc dir c8d742fa dev/active --json

  "short_id": "c8d742fa"

The answer is a name, not a reading of the tree: it resolves the same before anything is written there, and the command creates nothing.

The advisory report

Two ways to resolve an owner

artifactowner resolved from
b4d6e478-stray-plan.mdthe short id the name opens with
…-payment-reconciliation/review-notes.mdthe document reference naming it
…-payment-reconciliation/plan.mdreference — and it conforms, so it is not listed

The second row is a file sitting inside the epic's directory while a different issue's reference claims it. The third is the same shape, correctly placed.

A prefix-less name no issue references is passed over: nothing states who owns it.
The advisory report

Why the second rule exists

The convention drops the short-id prefix from filenames inside an issue directory. So every artifact created under the convention is prefix-less by construction.

A report that attributed owners only from filename prefixes would reach legacy flat artifacts and progressively fail to reach conforming ones — going blind exactly as the convention it advises on is adopted.

This was missed at design time. The epic's own independent review caught it against the epic's criteria, and it was fixed before the epic closed.
The advisory report

Advice, not enforcement

  • The command writes nothing and blocks no state transition.
  • It exits 0 whatever it finds — note exit=0 on the previous slide.
  • A listed artifact is left exactly where it is; acting on the report is the adopter's call.

A blocking validation rule was rejected deliberately: legacy flat artifacts are tolerated on purpose, so a cutover predicate would be a false-positive source rather than a signal.

The topmost offending path component is the one named, so a misplaced directory is one entry rather than one per file beneath it.
Archival

Every area is classified, out of the box

$ git init && jit init && jit config get documentation
  "development_root": "dev",   "archive_root": "dev/archive",

  "managed_paths":      dev/active  dev/studies  dev/sessions  dev/plans
                        dev/presentations  dev/design  dev/benchmarks
                        dev/experiments
  "permanent_paths":    dev/architecture  dev/eval  dev/vision
                        dev/index.md  dev/TESTING.md  dev/authoring-conventions.md
  "issue_scoped_areas": dev/active  dev/studies  dev/plans  dev/presentations

Scaffolded by jit init with no hand editing; array formatting condensed for the slide. dev/presentations is managed, dev/architecture permanent.

Archival

Managed and permanent are different questions

Managed

Move on archive. The area's contents are revision-specific work products of the issues that produced them.

Permanent

Archive by copy; the source stays. Living contributor documentation that readers still navigate to.

Classifying each area explicitly — rather than applying a blanket rule to the development root — is what keeps a living-documentation area from being swept into move-on-archive the first time a container that links it is archived.

A bare dev/ permanent entry was rejected: classification matches by path prefix, so it would silently make every managed area permanent.

Archival

The destination is named the same way

$ jit archive container c8d742fa --json     # epic:payment-reconciliation
  "destination_root": "dev/archive/c8d742fa-payment-reconciliation"

$ jit archive container b4d6e478 --json     # "Ledger import", no label
  "destination_root": "dev/archive/b4d6e478"

One derivation serves both the issue's artifact directory and its archive destination — the same normalizer, so the two can never disagree.

Execution writes a .jit-container marker holding the resolved full container id. The short id and the marker stay authoritative; the suffix is a human-readable aid.
Archival

What lies outside the development root is retained

$ jit archive container c8d742fa --json
  "eligible": true,  "blockers": [],
  "action_counts": { "move": 1, "copy": 0, "retain": 3, "block": 0 }

  retain  README.md          evidence: outside-development-root
  retain  scripts/regen.sh   evidence: outside-development-root
  retain  src/ledger.rs      evidence: outside-development-root
  move    dev/active/c8d742fa-payment-reconciliation/plan.md

All four are linked to the same container. Source files, scripts and repository-root documents keep their single copy, and discovery stops at them rather than walking through.

Archival

Retention was chosen on measurement

Classifying out-of-root artifacts as permanent was implemented first, then rejected: permanence sets keep-the-source while leaving wants-a-destination true, so copying fell out as an inherited consequence rather than a chosen behaviour.

Because discovery walks an unbounded transitive link closure through densely cross-linked documentation, that implementation scheduled, for this repository's 24 terminal containers, 684 copy operations over 139 distinct files — 16.6 MB of duplicated content, including seven frozen mirrors of the whole adopter documentation tree.

Which the project's own single-source invariant names as a staleness defect. The alternative was not argued; it was measured.
Archival

A directory link is navigation

The plan document above contains an ordinary markdown link to a directory:

Background in [the studies area](../../studies).

The plan is eligible with zero blockers. The directory target contributes no artifact entry, no edge, and no warning.

Rewriting the repository's own directory links was rejected as the fix: they are legitimate markdown, and the defect would have stayed shipped for every adopter.
Citations

Relocation breaks prose that validation cannot see

A path spelled out in a shell comment or a README is not a document reference. Nothing validates it, and moving the file silently invalidates it.

$ jit archive container c8d742fa --json
  moving-path-citation  README.md:3:20
  moving-path-citation  scripts/regen.sh:2:15

Every occurrence is its own warning, naming the citing file with a 1-based line and column. Only a relocating artifact earns them.

Matching only markdown link targets would have reached 2 of 26 measured citations, missing every shell-script line and both adopter-facing mentions — all inline code spans.
Citations

The scan universe is declared

The same container, before and after declaring where to look:

# default universe: the development root together with the permanent paths
  warnings: 0

# citation_scan_roots = ["dev", "scripts", "README.md"]
  moving-path-citation  README.md:3:20
  moving-path-citation  scripts/regen.sh:2:15

The default reaches the permanent paths; configuration widens it to executable and adopter-facing files outside the development root. Execution rewrites no document content: a citation inside a dated historical record must survive verbatim.

Citations

Identical without version control

The same repository with .git removed:

$ ls -d .git    ->  absent
  eligible: True   destination_root: dev/archive/c8d742fa-payment-reconciliation
  moving-path-citation  README.md:3:20
  moving-path-citation  scripts/regen.sh:2:15

Identical to the tracked run. Deriving the universe from version-control tracking was rejected for this reason: archival is a core command.

A tracking-derived warning set would silently empty without version control — reporting success by finding nothing.
Execution

Preview, then execute

$ jit archive container c8d742fa --execute
Archive execution complete: 2 publication(s), 1 reference change(s),
                            1 source deletion(s)

$ find dev/archive -type f | sort
dev/archive/c8d742fa-payment-reconciliation/.jit-container
dev/archive/c8d742fa-payment-reconciliation/active/…/plan.md

Beneath the destination root each artifact keeps its repository-relative source path, so a document archived out of an area is found again under the same area name. The marker holds the resolved full container id.

Execution

References follow; retained sources do not move

$ jit doc list c8d742fa
  - dev/archive/c8d742fa-payment-reconciliation/active/…/plan.md
  - src/ledger.rs
  - scripts/regen.sh
  - README.md

The relocated document's reference is relinked to its new path. The three retained artifacts keep both their location and their reference — src/ledger.rs, scripts/regen.sh and README.md are all still where they were.

A rerun of an already-archived container reconciles to a no-op.
Dogfooding

The cleanup ran through the mechanism

The repository's own development root was cleaned by running --execute once per terminal container — deliberately, so the repaired reference remapping was exercised on real artifacts and the run is itself the acceptance evidence.

Verification

The epic's own gate failed it twice

An independent adversarial review runs against the epic's criteria before it may close. Both failures were real, and neither was found by the lead.

  • One artifact was never archived. Its container's whole content was a single commit-pinned reference, which the planner retains by design. The criterion stated no commit-pin exception — so the pin was removed and the container archived, rather than the criterion amended.
  • The conformance report could not see prefix-less artifacts — the gap two slides back. The lead had recorded this and argued it was not a violation.
Recording a finding and dispositioning it does not make it out of scope. The reviewer's job is to disagree.
Verification

How the claims on these slides were checked

  • Product behaviour is shown on a freshly initialized repository, so no claim depends on this project's dogfood configuration.
  • Warning codes and blocker names were read from the emitting Rust source, not from prose about them.
  • The conformance change was measured by diffing the report before and after: 10 artifacts added, none removed and none changed.
  • Relocation was verified by git blob identity between the pre-run source and the archived destination.
Eligibility, exit status and action counts are all blind to a broken repository. A rehearsal ends in whole-repository validation, not in exit codes.
Honest limits

What is still open

  • An eligible plan can still refuse at execution in the general case. The instance that triggered it was fixed; the design question is open.
  • A directory link target is navigation to archival discovery and a missing asset to the link checker. The subsystems disagree.
  • Archival leaves empty source directories — invisible under version control, persistent without it.
  • The conformance report consults a document reference only to supply a missing owner, never to contradict a filename prefix.
Each is recorded against the criterion it was tested against, with the reason it is a follow-up rather than a violation.

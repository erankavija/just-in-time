The promise

The lifecycle is complete

Refresh

Turn intentional edits and new configuration into the next package state.

shipped One directory model · one composition graph · one recoverable publication path

The north star is not merely “apply a profile.” Apply-only made a profile effectively write-once. The completed epic adds the authoring, refresh, composition, ownership, upgrade, and exchange paths required to operate profiles over time.
Mental model

A profile is a declared repository change

package = manifest + sources · profile = tracked identity + ownership

The package declares

  • identity, compatibility, dependencies
  • workflow vocabulary and projections
  • whole files and managed regions
  • public variables and capture roots

The repository records

  • the worktree-relative package location
  • resolved public inputs
  • which profile owns each contribution
  • the exact published-base fingerprints

The manifest stays authoritative; the applied record is evidence, not shadow configuration.

This distinction prevents a second configuration database. Later operations re-read the package from the repository directory recorded at apply time.
Adopt

Adopt a workflow in one operation

mkdir my-project
cd my-project
cp -R <release>/packages .

jit init --profile path:packages/jit-dogfood
jit profile list
  • jit-dogfood brings its jit-default dependency with it.
  • Dependencies are sibling directories named by profile ID.
Keep the package directories where they were applied. Later validation and repair re-read them there.
A bare jit init stays methodology-neutral. The profile is what declares workflow vocabulary. Packages must be inside the worktree, and dependencies sit beside the selected package under directories named by their profile IDs.
Adopt

Read the package before applying it

jit profile show \
  --profile path:packages/jit-dogfood --json

# months later: exact-state verification
jit profile apply --profile id:jit-dogfood --dry-run

show reports identity, compatibility, dependencies, inputs, contributions, sources, targets, hashes, and any stored provenance.

path: introduces a package directory; id: later resolves the recorded profile and its remembered location.

Show answers “what is this package?” It does not verify current repository target bytes; use apply dry-run or profile validate for exact current-state checks.
Adopt

Preview the repository decision

jit profile diff \
  --profile path:packages/jit-dogfood

jit profile apply \
  --profile path:packages/jit-dogfood --dry-run --json

diff

Reports every decision and owner—even when publication cannot proceed.

--dry-run

Runs the exact publication planner and validation path, but writes nothing.

Diff answers “what would this package mean here?” Dry-run answers “would the real operation succeed?” Diff exits 4 when it reports conflicts; rehearsal fails where the corresponding publication would fail.
Compose

Profiles compose as declarations, not scripts

jit profile apply \
  --profile path:packages/sim-research \
  --dry-run
  1. Resolve dependencies and compatibility.
  2. Build one deterministic contribution graph.
  3. Deduplicate definitions that are semantically identical.
  4. Reject different definitions—selection order never chooses a winner.
sim-research can specialize a shared foundation without copying the foundation’s workflow inventory.
This is the first Claude/user-informed example. In gf2, sim-research depends on jit-default and adds research-specific brackets, tasks, rules, gates, projections, and agent guidance.
Operate

Ownership turns change into a decision

Repository vs published base vs candidateDecision
repository still equals the base; candidate is equalunchanged
repository still equals the base; candidate changedupdate
repository changed; candidate still equals the basediverged
repository and candidate changed differentlyconflict
unchanged, solely owned content disappears on upgraderemove

Shared content survives while another installed profile still owns it.

The point is not the names of internal types; it is the operator’s choice. JIT can update only when the repository still reflects the previous publication. Otherwise it reports who owns the content and refuses to guess.
Operate

Choose the verb by intent

IntentCommand
Understand a package or pending changeshow · diff
Check package, record, and owned contentvalidate
Install a selectionapply
Change declared public inputsreconfigure
Adopt intentional live repository editscapture
Replace an installed versionupgrade
Move a package between repositoriespack · add

Every mutation above supports --dry-run.

Capture is deliberately the one authoring and drift-adoption verb. There is no separate “bless drift” shortcut. Restore means the package remains authoritative; capture means the repository edit becomes the next package state.
User case

Drift asks: who should own this change?

IntentAction
The package remains authoritativerestore the published value
The repository edit becomes package contentprofile capture
A declared public input should changeprofile reconfigure
A newer package version should replace this oneprofile upgrade
repository target or registry → capture → package source or manifest

Capture folds owned semantic declarations and declared live assets back into the package, then republishes its tree whole.

Capture + reapply needs no version bump. Use upgrade only for a newer package version.

The human and JSON failure surfaces carry restore-or-capture guidance. Capture only reads targets declared by the manifest and only semantic contributions already claimed by that package’s applied record. This closes the dead-end Claude hit in gf2 on JIT 1.0.0, where capture refreshed files but not semantic contributions.
Contribute

Start with the repository that already works

  1. Decide the package boundary: what should travel together?
  2. Create packages/sim-research/manifest.toml.
  3. Declare every file, region, semantic contribution, and live root.
  4. Capture repository-authored material into the package.
  5. Rehearse in a clean repository; then pack it.
The manifest is an allowlist. Capture does not crawl the repository and invent a package.
This is the crucial contributor mental model. Capture is not magical inference. The contributor first states intent and ownership in the manifest; capture supplies bytes and current values for the declared repository-authored pieces.
Contribute

A valid v2 package starts this small

[profile]
manifest-version = 2
id = "sim-research"
version = "1.0.0"
compatible-jit = ">=1.0.0, <2.0.0"
  • id is lowercase-kebab; version is SemVer.
  • compatible-jit is a SemVer requirement for the binary.
  • Unknown fields and unsafe relative paths are rejected.
Author new packages as v2. Existing v1 package content still decodes; package and JIT versions remain independent.
This exact skeleton is parser-valid. All declaration arrays are optional, making it a good incremental starting point.
Contribute

Four declarations cover the repository surface

Manifest blockWhat it owns
[[contribution]]one typed configuration or registry declaration
[[asset]]one complete file at a declared target
[[region]]one marked region inside a repository file
[[live-source]]one repository area capture must fully account for

Dependencies and incompatibilities define the package graph; variables parameterize supported values and generated text.

The complete semantic contribution families are scalar, map-entry, set-string, keyed-array, and projection. Contributors should use the canonical profiles reference for each target’s complete value contract.

Capture adopts only declared repository-authored material. It never silently absorbs an unrelated file.
This boundary came directly from execution feedback. Generated regions and install-only assets remain package-authored; live assets and contributions owned by the applied package may be refreshed from repository state.
Contribute

Declare meaning—not a file patch

[[contribution]]
kind = "map-entry"
target = "type-hierarchy-types"
identity = "experiment"
value = 4

The kind defines merge semantics. Identical entries can share ownership; different values for the same identity conflict before publication.

Every contribution value is complete. An overlay is not a partial patch.
sim-research is an overlay: it depends on a shared base and adds only the research vocabulary. This keeps workflow inventories single-sourced and lets independent packages safely restate a genuinely shared definition.
Contribute

Variables are public, deterministic configuration

[[variable]]
name = "PROJECT_NAME"
default = "simulation"
env = "JIT_PROFILE_PROJECT_NAME"
default → values file → declared environment → repeated --set

Use {{jit:var:PROJECT_NAME}} only in supported templated bodies and description fields.

Profiles expose no secret input, interpolation, persistence, or audit channel.
The final set value wins. Resolved values are recorded so reconfiguration is deterministic. Audit events record variable names and source kinds, never values.
Contribute

Capture creates—and later refreshes—the package

declared live repository state → capture → complete package tree
jit profile capture \
  --source packages/sim-research \
  --destination packages/sim-research \
  --dry-run --json

# repeat without --dry-run to publish
  • Reads only manifest-declared targets.
  • Rejects unsafe paths, links, and undeclared executable content.
  • Republishes the tree whole; removed declarations cannot leave stale sources.
The destination can equal the source for an in-place refresh. Dry-run validates the exact tree publication without writing it.

mkdir ../scratch && cd ../scratch

Share

Pack one deterministic offline artifact

jit profile pack \
  --source packages/sim-research \
  --output dist/sim-research.tar \
  --dry-run

jit profile pack \
  --source packages/sim-research \
  --output dist/sim-research.tar
  • The archive carries package ID, version, and content digest.
  • Packing identical content produces identical bytes.
  • The digest proves integrity—not who supplied the archive.
JIT deliberately does not fetch or publish to a registry. The archive travels over the channel the adopter already trusts: a release, source control, USB, or another offline transport.
Share

Verify, add, rehearse, apply

jit profile add --archive sim-research.tar \
  --destination packages/sim-research --dry-run
jit profile add --archive sim-research.tar \
  --destination packages/sim-research

jit profile apply --profile path:packages/sim-research \
  --dry-run
jit profile apply --profile path:packages/sim-research

add recomputes the identity and rejects digest mismatch, traversal, links, unexpected modes, malformed content, and an occupied destination.

Dependencies also need to be present as sibling package directories. A refused add publishes nothing; apply then uses the same package graph and transaction path as every other lifecycle mutation.

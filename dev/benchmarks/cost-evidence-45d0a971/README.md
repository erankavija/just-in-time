# Cost evidence for the one-mutation-path epic, base against tip (jit:45d0a971)

Measures the four REQ-22 cost claims of epic b697a3f7 on a pinned pre-change binary
and on the tip, with every threshold computed inside one run. Figures below are
copied from [`summary.json`](summary.json), which [`validate.py`](validate.py)
rederives from `raw/`; run `python3 -I dev/benchmarks/cost-evidence-45d0a971/validate.py`
to check them.

## Harness, builds, and conditions

- **Harness:** [`scripts/benchmark-cost-evidence.sh`](../../../scripts/benchmark-cost-evidence.sh).
  `--base-only` records `raw/base/`; `<tip-binary>` records `raw/tip/` (base and tip,
  alternating order each round). Five samples per point; the reported figure is the
  median. Fixtures are generated by the binary under test and run on tmpfs.
- **Base:** `369d35a42f0ecc5067d930415c44908defdc0e36`, built by the harness in a
  `git archive` extraction with `cargo build --release --locked -p jit`; sha256
  `b5ba9298e54fda902b68858b8e7a930e6b29669df5e2fb11bb5f4420d126da4a`.
- **Tip:** main at `1d8d1497c`, built with the same profile; sha256
  `c35a80d968921ef6dbf41c93e7d0d9027a62276d8ec5b92514f646b6dbda3eb9`. `raw/tip/host.json` records no
  commit for the tip binary.
- **Harness commits:** `raw/base/` records `harness_head` `75c433e70` with the M in {10, 160}
  change not yet committed; `5180958a2` commits that change, and `raw/tip/` records
  `fc205d494`, which adds only the base record.
- **Machine:** AMD Ryzen 9 5900X 12-Core Processor, 24 logical cores, Linux 7.2.14-arch1-1, strace -- version 7.3,
  fixtures on tmpfs. The harness waits for a 1-minute load below

## Scenarios and method

- **(a) bulk:** `jit issue update --filter label:bench:match --state in_progress --json`
  over M in {10, 160} matches among N in {500, 2000} issues; per-match slope
  s(N) = (t(M=160) - t(M=10)) / 150.
- **(b) archive:** `jit archive candidates --json` over C in {10, 40} terminal
  containers; per-candidate slope and `config.toml` `openat` count under strace.
- **(c) dep:** `jit dep add` over minimal and inflated declarations (2,000 namespace
  values, 300 rules); D = t(inflated) - t(minimal).
- **(d) profile:** `jit profile add` of one 48-file package over four nested
  directories; directory `openat` and `fsync` counts under strace.

**M in {10, 160}.** The first design measured scenario (a) over M in {10, 40}.
The user decided, before any tip record, to widen the span to {10, 160}: the
per-match slope at M = 40 was about 0.2 ms, below timing noise, while instruction
and syscall counts were flat. N in {500, 2000} and the tip threshold are unchanged.
The earlier base record was discarded and retaken under the new method.

## Directory-sync outcome (REQ-05)

Issue 4d834432 (commit `c0bb74d5c`, closed at `6f8cb9798`) settled REQ-15 in favour
of coalescing: `prop_replay_converges_from_any_subset_of_persisted_operations` holds
on both backends, so redo apply syncs each changed directory once per record, after
its last operation and before the record is removed, while staged-file and event-log
data syncs stay per operation. The policy is stated in the `redo_apply.rs` module
rustdoc. The tip's directory fsyncs above fall accordingly.

## Deviations

- The tip run started at a 1-minute load of 1.77 and ended at 1.33. The harness gated at its default
  threshold of 2.0; the lead's protocol asked for below 1. The run was not repeated.
  Base and tip alternate within each round under the same load, and the tip passes
  every threshold with margin.

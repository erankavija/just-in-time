# Paths that are actual inputs to the production `jit` binary.
#
# This is the ONE inventory behind both questions asked about them:
#
#   - the running binary's freshness, which `is_binary_build_input`
#     (build_provenance.rs) answers by parsing this file into the same
#     `RepositoryInputs` declaration a quality gate states its checker's inputs
#     in, and matching with the same covering rule;
#   - the dirty flag recorded when the binary is installed, which
#     `scripts/install-jit.sh` answers by handing these lines to `git status`
#     as pathspecs.
#
# Neither consumer restates the list, so neither can drift from the other. That
# the two matchers — the covering rule and git's pathspec matching — select the
# same files is not assumed either: `build_provenance`'s conformance test holds
# them against each other over this repository's own file set.
#
# It is a positive inventory, not a denylist of paths presumed safe. The source
# and manifest roots cover Cargo's compilation inputs; the hook paths cover the
# files embedded by `include_str!` in production code. A newly added path
# elsewhere in the repository is therefore irrelevant to the binary by
# construction.
#
# One repository-relative path per line. A line naming a directory covers
# everything beneath it. Blank lines and `#` comments are ignored.
